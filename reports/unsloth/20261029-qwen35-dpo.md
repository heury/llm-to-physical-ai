# Qwen3.5 4B DPO 노트북 저장 및 정적 검증

## 변경

- 대상: `unsloth/Qwen3_5_(4B)-DPO.ipynb`.
- 원본: https://github.com/unslothai/notebooks/blob/main/nb/Zephyr_%287B%29-DPO.ipynb
- 다운로드한 원본 SHA-256: `bb43b6113eb76e3b458d1a9627896d2e3ba786deadb1cab2ffd842561d469b67`. main 브랜치에서 받은 사본이며 commit revision은 고정하지 않았다.
- 모델을 `unsloth/Qwen3.5-4B`로 변경. 기존 FastLanguageModel 로더가 Qwen3.5를 FastModel로 위임하는 로컬 소스를 확인했다. FP16 대신 BF16 지원 장치에서 BF16, 그 외 FP32를 선택한다.
- Zephyr 전용 역할 토큰 처리 대신 Qwen3.5 자체 채팅 템플릿을 사용한다. `enable_thinking=False`로 prompt를 렌더링하고 전체 대화가 해당 prompt로 시작하는지 검사한 뒤 응답만 추출한다. TRL의 EOS 추가에 맞춰 응답 끝 템플릿 EOS와 개행을 제거한다.
- 원본의 UltraFeedback train_prefs 0.5%, test_prefs 분리, rank 64/alpha 64, batch 2/누적 4, 3에포크, 학습률 5e-6을 유지한다.
- 현재 TRL API에 맞춰 beta/max_length를 DPOConfig에, tokenizer를 processing_class에 전달한다. 제거된 max_prompt_length=512 설정은 사용하지 않으며 전체 길이 1024를 적용한다. 이로 인해 원본의 prompt별 절단 정책과는 차이가 있다.
- 설치·뉴스·소개 셀과 저장된 출력, 실행 번호, Colab widget 메타데이터를 제거했다. 출처와 LGPL-3.0 안내는 보존했다.
- 실행 시 저장 경로는 `outputs/unsloth/<한국 시간 실행 ID>/`. trainer 결과, 지표, 최종 adapter와 tokenizer를 저장한다. 자동 업로드는 수행하지 않는다.

## 검증

작업 디렉토리: 저장소 루트 `/home/mind4u/dev/llm_playground`.

```bash
unsloth/.venv/bin/python outputs/unsloth/20261029-qwen35-dpo/validate.py
git diff --check
```

- nbformat 형식 검증 통과.
- Python 코드 셀 9개 AST 구문 검사 통과. 설치 셀과 저장된 출력 없음.
- 로컬 설치 TRL 소스와 DPOTrainer 생성자 키워드 및 DPOConfig의 beta/max_length 필드를 정적으로 비교했다.
- 모델 저장소에서 가져온 실제 `chat_template.jinja`를 Transformers Jinja 렌더러로 실행했다. 단일 턴, system 포함, 여러 턴 문맥 3건에서 공통 prompt와 chosen/rejected 응답 분리가 올바른 것을 확인했다. 다른 문맥의 선호 쌍은 ValueError로 거부한다.
- 결과: `outputs/unsloth/20261029-qwen35-dpo/validation.json`.
- 검증 환경의 정확한 패키지 버전은 같은 디렉토리 `versions.json`에 기록한다. 학습 환경 설치나 패키지 변경은 하지 않았다.

## 한계

GPU 모델 로딩, 양자화, 실제 UltraFeedback 다운로드·전체 전처리, Trainer 인스턴스 생성, 순전파·역전파 및 학습은 실행하지 않았다. 채팅 테스트는 실제 모델의 Jinja 템플릿과 최소 tokenizer 인터페이스로 수행했으며 토큰 ID 수준 검증은 아니다. 모델·데이터 리비전은 노트북에서 고정하지 않았으므로 실행 시 최신 기본 리비전이 사용된다. GPU 호환성·메모리·실제 학습 성공은 별도 검증이 필요하다.
