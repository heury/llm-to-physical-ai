# MiniMind 스팸 분류 모델 설계·구현 프롬프트

## 목표

이 저장소의 MiniMind를 기반으로 문자를 입력하면 바로 `정상` 또는 `스팸`을 출력하는 모델을 설계하고 구현해 주세요. 먼저 아래의 합의된 설계를 확인하고 프로젝트의 README와 실제 코드에 맞춰 작업하세요.

## 대화에서 확정한 설계

- 일반 텍스트를 생성해서 `0`/`1`을 답하게 하는 방식이 아니라, 기존 `lm_head` 자체를 정상·스팸 분류 헤드로 교체합니다.
- MiniMind Transformer 백본과 입력 토큰 임베딩은 재사용합니다.
- 기존 `Linear(hidden_size, vocab_size, bias=False)`를 `Linear(hidden_size, 2, bias=True)`로 교체합니다.
- 별도 decision MLP나 기존 어휘 출력 뒤에 추가하는 분류층은 사용하지 않습니다. 교체한 `lm_head`가 직접 두 클래스의 점수를 출력합니다.
- 클래스 매핑은 `0 = ham = 정상`, `1 = spam = 스팸`으로 고정합니다.
- 모델은 `[배치 크기, 2]` 형태의 logits를 반환하고, 사용자 화면에서는 이를 `정상` 또는 `스팸`으로 표시합니다.
- 추론은 한 번의 순전파로 처리합니다. `generate()`, 토큰 샘플링, 답변 문자열 파싱은 필요하지 않습니다.

```text
문자 입력
  → 토크나이저
  → [BOS] 문자 내용 [EOS]
  → MiniMind 백본
  → 마지막 유효 토큰(EOS)의 벡터
  → 교체한 lm_head: Linear(hidden_size, 2)
  → 정상 점수 / 스팸 점수
  → 정상 / 스팸
```

## 모델 세부 요구사항

1. `minimind/model/model_minimind.py`의 `MiniMindConfig`, `MiniMindModel`, `MiniMindForCausalLM`을 확인하고 백본을 재사용하세요. 다른 MiniMind 프로젝트의 동명 파일과 구분하세요.
2. 일반 언어 모델 경로를 보존할 수 있도록 별도의 스팸 분류 클래스에서 이 구조를 구현하는 것을 기본으로 하세요. 이 클래스 안에서는 `lm_head`를 이진 분류 헤드로 정의하세요.
3. 입력 임베딩은 기존 `vocab_size`를 유지하세요. 입력 임베딩과 분류 헤드는 크기가 다르므로 `tie_word_embeddings`를 해제하고 두 가중치가 공유되지 않도록 하세요.
4. causal attention을 유지하세요. 문자 전체를 읽을 수 있는 EOS 위치의 hidden state를 선택해 분류하세요.
5. 토큰화는 실제 토크나이저의 special token 설정을 확인하고 BOS/EOS가 중복되지 않게 구성하세요. 최대 길이로 자를 때도 EOS 자리를 확보하세요.
6. 오른쪽 패딩을 기본으로 한다면 마지막 유효 위치는 `attention_mask.sum(dim=1) - 1`로 구할 수 있습니다. 이 식을 왼쪽 패딩에 그대로 적용하지 마세요. 지원하는 패딩 방향을 명시하고, 패딩 위치를 분류에 사용하지 않도록 하세요.
7. 빈 문자·전체 패딩·길이 초과 입력에 대한 처리 규칙을 정하세요. 전체 패딩 입력에서 잘못된 인덱스를 조용히 사용하지 마세요.

## 데이터

첫 실험은 UCI SMS Spam Collection을 사용합니다.

- 원본: https://archive.ics.uci.edu/dataset/228/sms+spam+collection
- 영어 SMS 약 5,574건이며 원본은 `라벨<TAB>문자 본문` 형식입니다.
- `ham`은 정상, `spam`은 스팸입니다.
- 원본에는 판단 이유나 정답 확률 분포가 없습니다.
- `LocalLLaMA/typed-decisions`에서 논의했던 `state/questions/gold` 구조를 도입할 필요는 없습니다. 문자와 클래스 정답만 사용합니다.

변환 형식 예시:

```json
{"text": "Ok lar... Joking wif u oni...", "label": 0}
{"text": "Free entry in 2 a wkly comp...", "label": 1}
```

두 번째 문장은 원본의 일부를 줄여 표시한 형식 예시입니다. 실제 학습에는 원문을 사용하세요.

URL, 전화번호, 금액, 특수문자는 판정 단서가 될 수 있으므로 초기에는 보존하세요. 입력 길이 분포를 확인해 최대 토큰 수를 정하고, 잘림으로 인해 문자 끝의 URL이나 요금 안내가 사라지는 영향을 확인하세요.

학습·검증·테스트를 분리하고 동일하거나 매우 유사한 문구가 서로 다른 분할에 들어가지 않도록 하세요. 분할 시드와 방법을 기록하세요. 영어 UCI 데이터의 성능을 한국어 스팸 판정 성능으로 해석하지 마세요.

## 학습

- 실제 사용 가능한 사전 학습 가중치와 토크나이저를 확인하세요. 파일이 존재한다고 가정하지 마세요.
- 기존 언어 모델에서 백본 가중치를 가져오되, 기존 `lm_head.weight`는 제외하고 새 헤드를 초기화하세요. 크기가 다른 가중치는 `strict=False`만으로 자동 제외되지 않습니다.
- 백본 고정 후 헤드 학습을 기준 실험으로 삼고, 필요하면 백본까지 작은 학습률로 미세 조정해 비교하세요.
- labels는 `[배치 크기]` 형태의 정수 클래스입니다.
- 손실은 `CrossEntropyLoss(logits, labels)`를 사용합니다. 기존 다음 토큰 예측의 한 칸 이동과 토큰별 정답 마스킹은 사용하지 않습니다.
- 클래스 불균형을 확인하고 필요할 때 클래스 가중치를 검토하세요. MoE를 지원한다면 기존 보조 손실의 처리 여부를 명시하세요.
- 모델 구조를 구현했다고 스팸 판정 능력이 생기는 것은 아닙니다. 새 헤드는 학습 전 무작위 상태라는 점을 명시하세요.

## 추론 및 저장

- 기본 판정은 `logits.argmax(dim=-1)`입니다.
- 필요하면 softmax의 스팸 점수에 검증 데이터로 정한 임계값을 적용하세요. 테스트 데이터를 임계값 선택에 사용하지 마세요.
- softmax 점수를 보정된 실제 확률이라고 단정하지 마세요.
- 사용자 출력 예시: `문자: 오늘 회의는 오후 3시입니다. → 정상`.
- 프로그램 시작 시 모델을 한 번 로드하고 입력마다 재사용하세요.
- 백본·분류 헤드 가중치, 모델 설정, 토크나이저, 라벨 매핑, 입력 길이·special token·패딩 정책, 사용하는 경우 임계값을 함께 저장하세요.

## 검증 및 결과 보고

- 작은 설정으로 순전파·역전파를 검증하고 logits shape, 백본으로의 gradient 전달, 임베딩과 헤드의 비공유를 확인하세요.
- 가변 길이 배치에서 패딩 유무에 따른 판정 점수의 일관성을 확인하세요.
- 기존 언어 모델 백본 로딩과 분류 모델 저장·재로딩이 올바른지 확인하세요.
- 실제 학습 후에는 스팸 precision·recall·F1, 정상 문자 오탐률, 혼동 행렬을 기록하세요. 학습 전 smoke 검증과 실제 분류 성능 평가를 구분하세요.
- 실행은 프로젝트 디렉토리를 기준으로 하고 산출물은 저장소 루트의 `outputs/minimind/<실행 ID>/`, 보고서는 `reports/minimind/<실행 ID>.md`에 저장하세요.
- 학습 실행과 외부 데이터 다운로드는 별도의 실행 범위로 명시하고, 클라우드 리소스는 요청 없이 생성하지 마세요.
- 마지막에 변경 파일, 실행한 검증, 미실행 항목, 학습·추론 명령과 남은 한계를 설명하세요.
