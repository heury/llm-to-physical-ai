사용자 요청과 주요 답변을 대화 순서대로 정리했다. agent 항목은 실행·검증 결과 요약이며 도구 호출 원문, 환경 설정 메시지, 인증 정보는 제외했다. 진행률은 각 답변 당시 확인한 값이며, 이 문서를 작성하면서 클라우드의 최신 상태를 다시 조회하지는 않았다.

## user — train_agent.py 원격 학습 요청

caspar/agent-rl-en 데이터를 이용하여 train_agent.py 학습 진행해.
베이스 모델은 caspar/MiniMind-Dense-64M-Mixed-SFT-v1.0을 사용하고, 보상 모델은 Skywork/Skywork-Reward-V2-Qwen3-1.7B을 이용해. 학습에 관련된 명령어는 아래 샘플을 참고해.

runpod에서 rtx 5090 pod을 이용해서 학습을 진행하고, 학습이 완료되면 결과와 샘플 테스트를 보고하고, 모델을 huggingface에 업로드후 pod는 제거해.

```bash
# Use sglang for rollout
# Start sglang server first:
python -m sglang.launch_server --model-path ./minimind-3 --attention-backend triton --host 0.0.0.0 --port 8998
# Training parameters for reference:
python train_agent.py --rollout_engine sglang --sglang_base_url http://localhost:8998 --sglang_shared_path ./ckpt_mm --data_path ../dataset/agent_rl_math.jsonl --use_wandb
```

위 명령은 사용자 제공 참고 예시이며, 실제 실행에서는 영어 데이터 경로와 로컬 전용 SGLang 주소를 사용했다.

## agent — 중단 확인 및 보상 재현

학습과 자동 업로드 서비스를 중단하고 Pod의 `stopped` 상태를 확인했다. 마지막 로그는 **3,946/7,549회**였고 최신 저장 체크포인트·로그·토크나이저를 보존했다. 저장 주기가 있으므로 체크포인트가 마지막 로그와 정확히 같은 단계라는 의미는 아니다.

해당 문장은 프로그램 예외가 아니라 모델 생성 응답이었다. 저장 모델을 로컬 CPU에서 실행해도 동일하게 재현됐으며 코드·데이터·템플릿에서 강제 반환 경로는 발견되지 않았다.

같은 `37*19` 질문에 실제 보상 함수를 적용했다.

| 응답 | 기존 보상 |
|---|---:|
| 거절 문장 | +0.140625 |
| 도구 없이 정답 703 | +0.701563 |
| 도구 없이 오답 700 | +0.068750 |
| 정상 호출 후 정답 | +3.000000 |
| 베이스 모델의 잘못된 배열형 호출 | -0.362223 |

Skywork의 거절 원시 점수 -3.59375를 10으로 나누고 길이 보상 +0.5를 더하면 +0.140625가 됐다.

초기 모델은 올바른 인자 대신 도구 스키마를 복사한 JSON 배열을 생성했다. 파서가 이를 무효 처리하면서 일반 응답 보상 분기로 들어갔고, 이 분기는 정답을 검사하지 않았다. 그룹 상대 보상에서는 같은 그룹의 다른 응답보다 높은 점수가 중요하다. 거절이 잘못된 호출보다 유리하다는 비교는 이 실패 경로를 뒷받침하지만, 모든 학습 그룹에 대한 인과 검증은 아니었다.

## agent — 보상 수정과 로컬 SFT 실험

현재 데이터셋의 `tools`와 비어 있지 않은 `gt`를 기준으로 도구 과제를 구분했다. 일반 대화는 기존 보상 모델을 사용한다.

| 사례 | 수정 전 | 수정 후 |
|---|---:|---:|
| 거절 | +0.141 | -1 |
| 정답이나 필수 도구 미사용 | +0.702 | -1 |
| 오답·도구 미사용 | +0.069 | -1 |
| 잘못된 호출 | -0.362 | -1.5 |
| 정상 실행·최종 정답 | +3 | +3 |

실제 실행 결과와 최종 답변이 모두 정답과 일치해야 최대 보상을 받도록 했다. `703`을 `1703`의 일부에서 찾아 정답으로 인정하던 문제도 수정했다. 보상·통합 테스트 18개와 토크나이저 테스트 4개가 통과했다. 최종 샘플 정답률이 출발 모델보다 개선되지 않으면 공개 업로드를 막는 조건을 추가했다.

별도로 원본 베이스 모델에서 계산 호출만 가르치는 로컬 SFT를 수행했다. Seed 42, batch 2, 학습률 2e-5, 120 updates였으며 도구 호출과 EOS만 지도학습했다.

같은 질문 형식의 미학습 계산식 8개에서 **정확한 도구 실행 0/8 → 7/8**, 유효한 단일 호출 8/8을 확인했다. 실패는 `96/8`을 `64/8`로 바꿔 호출한 사례였다.

이는 **호출 형식·계산 실행에 한정된 SFT 개선**이었다. 보상 수정 후 전체 RL의 성능이나 도구 결과를 받은 뒤 최종 답변까지 완성하는 능력을 검증한 결과는 아니었다.

## agent — 두 번째 실행의 문제

약 **5,210/7,549회, 69%**에서 연산은 안정적이었으나 목표 성능 개선은 확인되지 않았다.

| 항목 | 확인 결과 |
|---|---|
| 손실·가중치 | NaN·Inf 없음, 갱신 확인 |
| 초기/최근 200회 평균 보상 | -1.23 → -0.67 |
| 기대 도구 이름 호출 | 7/13 → 8/13 |
| 최종 정답 | 0/13 → 0/13 |
| 미완료 | 13개 모두 3턴 제한 도달 |

기대 도구 이름 호출은 인자 유효성을 보장하지 않는다. 계산 질문에서는 `37*19`의 결과 `703`을 받고도 같은 도구를 반복 호출했다. 다른 도구에서는 존재하지 않는 이름이나 잘못된 인자 키를 생성했다.

준비 SFT는 호출 형식만 학습했고 **도구 결과를 읽고 최종 답변으로 마치는 과정**은 학습하지 않았다. 또한 정상 호출 후 미완료는 -0.5, 미호출은 -1이므로 반복 호출이 상대적으로 유리할 수 있었다.

agent는 호출만 가르친 체크포인트 선택이 전체 상호작용의 문제를 해결하지 못했음을 인정했다. 중단 후 다섯 도구에 대해 **질문 → 호출 → 실행 결과 → 최종 답변** 전체 대화를 먼저 SFT하고, 반복·진행 없는 호출을 적절히 감점하는 방안을 권장했다.

이 검토에서는 학습 중단이나 정책 교체를 실행하지 않았다. 최종 업로드의 성능 개선 조건은 유지했다.
