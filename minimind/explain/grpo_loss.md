# 간단한 샘플로 이해하는 GRPO loss

GRPO는 같은 질문에 여러 응답을 생성하고, 그룹 평균보다 좋은 응답은 더 잘 나오도록, 나쁜 응답은 덜 나오도록 정책 모델을 학습합니다.

이 설명은 [trainer/train_grpo.py](../trainer/train_grpo.py)의 `--loss_type grpo` 경로를 기준으로 합니다. 파일의 기본 설정은 `cispo`이므로 아래 식을 사용하려면 `grpo`를 선택해야 합니다. 여기서는 학습을 실행하지 않고 코드의 계산 과정을 설명합니다.

## 1. DPO와 무엇이 다른가?

[DPO 예제](dpo_loss.md)에서는 데이터에 이미 지정된 chosen과 rejected를 비교했습니다. GRPO에서는 같은 질문에 여러 응답을 생성한 다음, 각 응답의 보상을 구해 그룹 안에서 비교합니다.

질문이 “1 + 1은?”이고 응답 두 개를 생성했다고 가정하겠습니다.

| 생성 응답 | 보상 |
|---|---:|
| `"2"` | 1 |
| `"3"` | 0 |

이 보상은 계산을 위한 가정입니다. 실제 `calculate_rewards()`는 보상 모델 점수에 길이, 생각 태그, 반복 관련 점수를 반영합니다. 단순히 정답이면 1, 오답이면 0을 반환하는 함수는 아닙니다.

우선 각 응답을 토큰 하나로 단순화하고 종료 토큰은 생략합니다. 실제 여러 토큰의 처리는 마지막에 연결합니다.

## 2. 보상을 advantage로 바꾸기

보상은 응답의 원래 점수이고, advantage는 **같은 질문에서 생성한 응답들의 평균보다 얼마나 좋은지**를 나타내는 상대 점수입니다.

```python
advantages = (rewards - mean_r) / (std_r + 1e-4)
```

보상이 `[1, 0]`이면 평균은 0.5입니다. 코드에서는 `unbiased=False`로 표준편차를 계산합니다.

```text
표준편차 = sqrt(((1 - 0.5)² + (0 - 0.5)²) / 2)
         = 0.5

응답 "2": (1 - 0.5) / (0.5 + 0.0001) ≈ +0.9998
응답 "3": (0 - 0.5) / (0.5 + 0.0001) ≈ -0.9998
```

이후 손계산에서는 편의를 위해 각각 **+1과 -1로 근사**합니다.

- 양수: 그룹 평균보다 좋은 응답이므로 확률을 높이는 방향으로 학습합니다.
- 음수: 그룹 평균보다 나쁜 응답이므로 확률을 낮추는 방향으로 학습합니다.
- 모든 보상이 같으면 advantage가 모두 0이므로 보상 항에서 학습 신호가 생기지 않습니다.

표준편차로 나누면 점수의 퍼진 정도를 기준으로 상대적인 차이를 표현할 수 있습니다. `0.0001`은 표준편차가 0일 때도 나눗셈이 가능하도록 하는 작은 값입니다. 여러 질문이 있다면 질문마다 따로 정규화합니다.

## 3. 세 가지 확률의 역할 구분하기

| 이름 | 의미 | 사용 목적 |
|---|---|---|
| old 정책 | 응답을 생성한 당시 정책 | 생성 당시보다 확률이 얼마나 바뀌었는지 비교 |
| 현재 정책 | 지금 업데이트하는 모델 | 학습 대상 |
| 참조 모델 | 고정된 기준 모델 | 기준 정책에서 벗어나는 변화에 비용 부과 |

old와 참조 모델은 역할이 다릅니다. 아래 예제에서는 숫자 계산을 단순하게 하려고 확률을 같게 정했습니다.

여기서 확률은 **문맥이 주어졌을 때 해당 토큰을 출력할 확률**입니다. 답이 정답일 확률이나 보정된 신뢰도를 뜻하지 않습니다.

## 4. 먼저 클리핑과 KL 없이 기본 손실 이해하기

다음과 같이 확률이 바뀌었다고 가정합니다. 나머지 확률은 다른 토큰들에 배정되어 있습니다.

| 응답 토큰 | old 확률 | 현재 확률 | advantage |
|---|---:|---:|---:|
| `"2"` | 0.4 | 0.44 | +1 |
| `"3"` | 0.4 | 0.36 | -1 |

먼저 현재 확률을 old 확률로 나눕니다.

```text
ratio("2") = 0.44 / 0.4 = 1.1
ratio("3") = 0.36 / 0.4 = 0.9
```

비율이 1보다 크면 출력 확률이 증가했고, 1보다 작으면 감소했습니다. 코드에서는 로그 확률을 사용하므로 다음과 같이 계산합니다.

```python
ratio = torch.exp(per_token_logps - old_per_token_logps)
```

클리핑과 KL을 잠시 제외한 토큰별 손실은 `-ratio × advantage`입니다.

| 응답 | 확률이 old와 같을 때 손실 | 현재 손실 |
|---|---:|---:|
| `"2"` | `-1 × (+1) = -1` | `-1.1 × (+1) = -1.1` |
| `"3"` | `-1 × (-1) = +1` | `-0.9 × (-1) = +0.9` |
| 평균 | 0 | -0.1 |

좋은 응답의 확률이 증가해도 손실이 줄고, 나쁜 응답의 확률이 감소해도 손실이 줄었습니다. 이 부호 구조가 학습 방향을 만듭니다. 실제 신경망에서는 여러 토큰이 매개변수를 공유하므로 각 확률이 독립적으로 조절되는 것은 아닙니다.

## 5. 클리핑으로 추가 이득 제한하기

한 번의 비교에서 확률을 지나치게 바꾸는 데 계속 이득을 주지 않도록 클리핑을 추가합니다. `epsilon=0.2`이면 범위는 `[0.8, 1.2]`입니다.

```python
clipped_ratio = torch.clamp(ratio, 0.8, 1.2)
objective = torch.min(
    ratio * advantages.unsqueeze(1),
    clipped_ratio * advantages.unsqueeze(1),
)
```

`objective`는 크게 만들고 싶은 값입니다. 두 값 중 작은 것을 선택하면, 클리핑으로 계산한 값보다 과도한 이득을 얻지 못합니다. 최종 손실에는 음수를 붙여 최소화합니다.

앞의 비율 `[1.1, 0.9]`는 범위 안이므로 계산 결과가 바뀌지 않습니다. 이번에는 현재 확률을 `[0.6, 0.2]`로 바꿔 보겠습니다.

| 응답 | advantage | ratio | clipped ratio | 최종 objective |
|---|---:|---:|---:|---:|
| `"2"` | +1 | 1.5 | 1.2 | `min(1.5, 1.2) = 1.2` |
| `"3"` | -1 | 0.5 | 0.8 | `min(-0.5, -0.8) = -0.8` |

음수 advantage에서는 곱셈의 부호에 주의해야 합니다. `-0.8`이 `-0.5`보다 작으므로 두 번째 값이 선택됩니다.

KL을 제외한 평균 손실은 다음과 같습니다.

```text
클리핑 전: (-1.5 + 0.5) / 2 = -0.5
클리핑 후: (-1.2 + 0.8) / 2 = -0.2
```

이 상태에서는 두 응답 모두 유리한 방향으로 클리핑 경계를 넘었습니다. 따라서 해당 보상 목적항은 평평해지고, 이 항에서 확률을 더 개선하는 방향의 기울기는 0입니다. 다음에 설명하는 KL 항은 여전히 영향을 줄 수 있습니다.

**클리핑은 실제 확률이나 비율을 범위 안에 강제로 가두지 않습니다.** 손실 계산에서 추가 이득을 제한합니다. 또한 advantage의 부호에 따라 작동 방향이 달라지므로, 범위를 벗어난 모든 경우에 기울기가 0이 되는 것은 아닙니다.

## 6. KL 페널티로 참조 모델과의 차이에 비용 더하기

클리핑은 old 정책과 비교합니다. 별도로 고정된 참조 모델에서 벗어나는 변화에도 비용을 부과합니다. 이것이 이 코드의 KL 페널티입니다.

코드는 생성된 각 토큰에 대해 다음 KL 추정 항을 계산합니다. 어휘 전체를 합산한 정확한 KL 값을 직접 계산하는 것은 아닙니다.

```python
kl_div = ref_per_token_logps - per_token_logps
per_token_kl = torch.exp(kl_div) - kl_div - 1
```

확률로 풀어 쓰면 다음과 같습니다. `log`는 자연로그입니다.

```text
q = 참조 확률 / 현재 확률
KL 항 = q - log(q) - 1
```

두 확률이 같으면 `q=1`이어서 비용은 0입니다. 비율이 1에서 벗어나면 양의 비용이 생깁니다.

먼저 클리핑이 작동하지 않았던 기본 사례로 돌아갑니다.

| 응답 | 참조 확률 | 현재 확률 | KL 항 |
|---|---:|---:|---:|
| `"2"` | 0.4 | 0.44 | 약 0.0044 |
| `"3"` | 0.4 | 0.36 | 약 0.0058 |

`beta=0.1`을 사용하면:

```text
토큰 손실 = -objective + beta × KL 항

"2" 손실 ≈ -1.1 + 0.1 × 0.0044 = -1.0996
"3" 손실 ≈ +0.9 + 0.1 × 0.0058 = +0.9006

평균 손실 ≈ -0.0995
```

보상 항만 있을 때의 `-0.1`에 작은 비용이 추가되었습니다. `beta`가 크면 이 비용의 영향이 커집니다.

클리핑이 작동하는 현재 확률 `[0.6, 0.2]` 사례도 계산하면:

```text
"2" KL 항 = 0.4/0.6 - log(0.4/0.6) - 1 ≈ 0.0721
"3" KL 항 = 0.4/0.2 - log(0.4/0.2) - 1 ≈ 0.3069

"2" 손실 ≈ -1.2 + 0.1 × 0.0721 = -1.1928
"3" 손실 ≈ +0.8 + 0.1 × 0.3069 = +0.8307

평균 손실 ≈ -0.1811
```

위 손계산은 advantage를 ±1로 근사했습니다. 실제 코드처럼 ±0.9998을 사용하면 소수점 아래 값이 조금 달라집니다.

## 7. 실제 응답이 여러 토큰이면?

같은 응답의 모든 토큰에 동일한 advantage를 사용합니다. 하지만 각 토큰의 확률은 질문과 앞선 응답 토큰에 따라 달라지므로 ratio와 KL 항은 토큰마다 계산합니다.

유효한 첫 EOS까지 포함하고, 패딩과 그 뒤의 토큰은 제외합니다. 다음은 평균 방식을 보여 주는 별도의 가상 손실입니다.

| 응답 | 토큰별 손실 | 마스크 | 응답별 평균 |
|---|---|---|---:|
| A | `[-0.8, -0.4, 99]` | `[1, 1, 0]` | `(-0.8 - 0.4) / 2 = -0.6` |
| B | `[0.3, 0.6, 0.9]` | `[1, 1, 1]` | `(0.3 + 0.6 + 0.9) / 3 = 0.6` |

A의 마지막 자리는 패딩이므로 가상의 값 `99`는 계산에서 제외합니다.

```text
최종 policy_loss = (-0.6 + 0.6) / 2 = 0
```

이 구현은 **응답별 유효 토큰 평균 → 응답 간 평균** 순서입니다. 모든 응답의 토큰을 한꺼번에 더한 뒤 전체 토큰 수로 나누는 방식과 다릅니다.

```python
policy_loss = (
    (per_token_loss * completion_mask).sum(dim=1)
    / completion_mask.sum(dim=1).clamp(min=1)
).mean()

loss = (policy_loss + aux_loss) / args.accumulation_steps
loss.backward()
```

MoE를 쓰지 않으면 `aux_loss=0`입니다. `accumulation_steps=1`이면 역전파할 손실은 `policy_loss`와 같습니다.

## 8. 손실값과 학습 방향은 구분하기

**음수 손실은 오류가 아닙니다.** 이 손실은 오답 개수가 아니라 최소화하기 위해 정의한 목적함수입니다. DPO의 `-log(sigmoid(...))`와 값의 크기나 부호를 직접 비교하지 않습니다.

**손실이 0이라고 기울기도 0인 것은 아닙니다.** 예를 들어 ratio가 모두 1이고 advantage가 +1과 -1이면 보상 손실의 평균은 0입니다. 하지만 두 항은 서로 다른 응답 확률에 의존하므로, 일반적으로 각각의 확률을 바꾸려는 학습 신호가 남을 수 있습니다. 실제 전체 기울기는 모델의 매개변수에 따라 결정됩니다.

또한 손실은 생성한 응답, 보상, old 확률에 따라 달라집니다. 여러 학습 단계의 손실 숫자만으로 모델 품질을 판단하기보다 보상과 실제 생성 응답도 함께 확인해야 합니다.
